# StarPony Insights

Внутренняя система аналитики для производственной компании StarPony. Показывает,
что продаётся, из чего это сделано, сколько материалов осталось и что пора закупать —
на данных учёта МойСклад.

Восемь разделов: главная со сводкой, товары и материалы в отгрузках, материалы
в приёмках, поставщики, расчёт производства, сроки оплаты, инвентаризация,
прибыльность и каналы продаж.

**Статус: фаза 1, фундамент.** Приложение ещё не развёрнуто.

---

## Стек

| Слой | Решение |
|---|---|
| Бэкенд | Python 3.12, Django 5.2 LTS, DRF, PostgreSQL 18 |
| Сервер приложения | gunicorn |
| Фронтенд | React 19, TypeScript, Vite, Tailwind, shadcn/ui |
| Данные на фронте | TanStack Query, TanStack Table, nuqs |
| Контракт API | drf-spectacular → openapi-typescript |
| Инфраструктура | Docker, Caddy, деплой через GitHub Actions |

Монорепозиторий: один push — одна версия системы, контракт API и фронтенд
не разъезжаются.

---

## Как это устроено

```
браузер → Caddy ─┬→ статика фронтенда
                 └→ gunicorn → Django
                        ↓
                    Postgres
```

Три контейнера, наружу смотрит только Caddy.

**Источник правды — Postgres, а не МойСклад.** В учётную систему ходят только
синхронизации по расписанию и обратная запись; ни один HTTP-запрос пользователя
не идёт в чужой API. Лимит запросов к МойСкладу общий с другими системами компании,
поэтому клиент читает заголовки остатка лимита и притормаживает заранее.

## Структура

```
backend/
├── config/        settings, urls, wsgi
├── core/models/   модели домена — одно место
├── moysklad/      клиент, синхронизации, обратная запись
├── api/           по разделам: urls, serializers, views, services
└── tests/

frontend/src/
├── app/           оболочка: роутер, провайдеры, раскладка
├── sections/      одна папка = один пункт меню
├── shared/        то, что понадобилось второму разделу
└── styles/
```

Фронтенд делится по разделам, а не по типам файлов: правка одной страницы
не должна требовать четырёх папок в разных концах дерева.
